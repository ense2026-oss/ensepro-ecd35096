# แก้ปุ่ม "เข้า OT / ออก OT" ในหน้าเช็คอิน

## ปัญหา
ปุ่ม "เข้า OT" ในหน้าเช็คอินสร้างคำขอโอทีลงตาราง `overtime_requests` โดยตรง (สถานะ pending) และปุ่ม "ออก OT" ไปแก้เวลาในคำขอนั้น ทำให้พนักงานสร้างคำขอโอทีได้โดยไม่ผ่านหน้ายื่นคำขอโอที

## สิ่งที่จะแก้

### 1. ปุ่มโอทีไม่สร้างคำขออีกต่อไป
- ถ้า "วันนี้ยังไม่มีคำขอโอทีที่อนุมัติ" → แท็บโอทีจะแสดงข้อความว่าต้องยื่นคำขอผ่านระบบก่อน พร้อมปุ่มที่พาไปหน้า "ยื่นคำขอโอที" (/overtime)
- ยกเลิกการ insert/update `overtime_requests` จากหน้าเช็คอินทั้งหมด

### 2. บันทึกเวลาโอทีจริง แยกจากเวลาที่ขอไว้
- ถ้าวันนี้มีคำขอโอทีที่ "อนุมัติแล้ว" → ปุ่ม "เข้า OT / ออก OT" ใช้งานได้ตามปกติ (ยังต้องอยู่ในพื้นที่ที่กำหนด)
- เวลาที่กดจะถูกเก็บเป็น "เวลาจริง" แยกต่างหาก ไม่ทับเวลาที่ขออนุมัติไว้
- ตารางประวัติในหน้าเช็คอินจะแสดงเวลาโอทีจริง (ถ้ายังไม่กด แสดงเวลาที่ขอไว้เป็นค่าอ้างอิง)

### 3. สถานะที่แสดง
- ยังไม่มีคำขออนุมัติ → "ต้องยื่นคำขอโอทีก่อน"
- คำขอรออนุมัติ → "คำขอโอทีรออนุมัติ" (กดไม่ได้)
- อนุมัติแล้ว → ปุ่มเข้า/ออก OT ทำงาน
- กดออก OT แล้ว → "บันทึกโอทีวันนี้เรียบร้อย"

## รายละเอียดทางเทคนิค
- Migration: เพิ่มคอลัมน์ `ot_actual_in text` และ `ot_actual_out text` ใน `public.check_in_records` (ค่าเริ่มต้นว่าง) เพื่อเก็บเวลาโอทีจริงแยกจาก `overtime_requests`
- `src/pages/CheckIn.tsx`
  - ลบ `handleOtCheckIn` เดิม (insert overtime_requests) และ `handleOtCheckOut` เดิม (update start/end/hours + notifyApprovers)
  - เพิ่ม logic: หา OT ของวันนี้ที่ `status = 'approved'` เพื่อเปิดใช้งานปุ่ม
  - ปุ่มใหม่บันทึก `ot_actual_in` / `ot_actual_out` ลงแถว `check_in_records` ของวันนี้ (ถ้ายังไม่มีแถวจะสร้างแถวจากการเช็คอินตามปกติก่อน)
  - กรณีไม่มีคำขออนุมัติ ใช้ `navigate("/overtime")`
  - คอลัมน์ "เข้า OT / ออก OT" ในตารางประวัติอ่านจากเวลาจริงก่อน แล้วค่อย fallback ไปที่เวลาในคำขอ
- ไม่แตะหน้า /overtime และ flow การอนุมัติเดิม
