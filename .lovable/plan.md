# แก้ไขฟอร์มเพิ่ม/แก้ไขข้อมูลพนักงาน

## ปัญหาที่ตรวจพบ

1. **ตัวเลือกสิทธิ์การใช้งานไม่ตรงกับหน้าตั้งค่า**
   - ตอนนี้ dropdown เรียงตามลิสต์ที่ hardcode ไว้ในโค้ด (`executive, manager, team_lead, hr, ...`) ไม่ได้เรียงตาม "ลำดับ" ที่ตั้งไว้ในหน้าสิทธิ์ผู้ใช้งาน
   - ป้ายชื่อแสดงเฉพาะคำอธิบายภาษาไทย ไม่เห็นชื่อ Role จริง (English) ที่ระบบใช้
2. **สิทธิ์ของพนักงานอาจถูกเปลี่ยนโดยไม่ตั้งใจ**
   - ค่าที่เก็บในพนักงานเป็นตัวใหญ่ (`Employee`, `HR`) ส่วนในตั้งค่าเป็นตัวเล็ก (`employee`, `hr`) ถ้าค่าปัจจุบันไม่ตรงกับรายการใดเลย เบราว์เซอร์จะเลือกตัวเลือกแรกให้อัตโนมัติ → กดบันทึกแล้วสิทธิ์เปลี่ยนเงียบๆ
3. **ฟิลด์ที่มีในฐานข้อมูลแต่ไม่มีในฟอร์ม** จึงแก้ไขไม่ได้จริง: เพศ, กะการทำงาน, วันสิ้นสุดทดลองงาน, วันสิ้นสุดสัญญา, เลขบัญชีธนาคาร, ใบขับขี่, จำนวนบุตรชาย/หญิง
4. **ไม่มีการแจ้งผลจริง** — หน้าจอขึ้น "สำเร็จ" ทันทีโดยไม่รอผลบันทึก ถ้าบันทึกล้มเหลว (เช่น ซิงก์สิทธิ์ไม่ผ่าน) ผู้ใช้จะไม่รู้

## สิ่งที่จะทำ

### 1. สิทธิ์การใช้งาน (จุดหลัก)
- ดึงรายการ Role จากหน้าตั้งค่า (`role_permissions`) และ **เรียงตามลำดับ display_order ที่ผู้ใช้กำหนดเอง** แทนลำดับ hardcode
- แสดงตัวเลือกเป็น `Executive — ผู้บริหาร` (ชื่ออังกฤษ + คำอธิบายไทย) ให้ชัดเจน
- จับคู่ค่าปัจจุบันแบบไม่สนตัวพิมพ์ใหญ่-เล็ก เพื่อให้ค่าที่เก็บอยู่แสดงถูกต้องเสมอ
- ถ้าพนักงานมีสิทธิ์ที่ถูกลบไปจากหน้าตั้งค่าแล้ว จะแสดงเป็นตัวเลือกพิเศษ "(ไม่มีในการตั้งค่าแล้ว)" พร้อมข้อความเตือน ไม่เปลี่ยนค่าอัตโนมัติ
- เพิ่มคำอธิบายใต้ช่อง: การเปลี่ยนสิทธิ์จะมีผลกับบัญชีเข้าใช้งานของพนักงานคนนั้นทันที

### 2. เพิ่มฟิลด์ที่ขาด
- ข้อมูลพื้นฐาน: เพศ
- ข้อมูลการทำงาน: กะการทำงาน (ดึงจากรายการกะจริงในระบบ), วันสิ้นสุดทดลองงาน, วันสิ้นสุดสัญญา
- ข้อมูลอื่น: เลขบัญชีธนาคาร, เลขใบขับขี่
- ครอบครัว: จำนวนบุตรชาย / บุตรสาว

### 3. การบันทึกให้ใช้งานได้จริง
- รอผลการบันทึกจริงก่อนแจ้งผล และแสดงข้อความผิดพลาดจริงเมื่อบันทึกไม่สำเร็จ
- ปุ่มบันทึกแสดงสถานะกำลังบันทึกและกดซ้ำไม่ได้
- ตรวจรูปแบบอีเมลก่อนบันทึก และแจ้งเตือนถ้าปล่อยว่าง (จะสร้างบัญชีเข้าใช้งานให้ไม่ได้)
- รายงานผลการซิงก์สิทธิ์กลับมาที่หน้าจอ (สำเร็จ / พนักงานยังไม่มีบัญชีผู้ใช้ / ล้มเหลว)

## รายละเอียดทางเทคนิค

- `src/hooks/useRoleOptions.ts`: ใช้ลำดับจาก `role_permissions.display_order` (เพิ่ม order ที่ `getAllRoles` ส่งออก), label = `Name — description`, เพิ่ม helper จับคู่ค่าแบบ case-insensitive
- `src/contexts/PermissionsContext.tsx`: `getAllRoles()` ส่ง `display_order` ออกมาด้วย (ปัจจุบัน query เรียงตาม display_order อยู่แล้ว)
- `src/components/employees/EmployeeFormDialog.tsx`: เพิ่มฟิลด์ที่ขาด, normalize ค่า role ตอนเปิดฟอร์ม, fallback option, สถานะ saving, validate เพิ่ม
- `src/pages/Employees.tsx`: `handleFormSave` เป็น async + try/catch + toast ตามผลจริง, ปิด dialog หลังบันทึกสำเร็จเท่านั้น
- ไม่มีการเปลี่ยนโครงสร้างฐานข้อมูล ทุกฟิลด์มี column รองรับและ mapping ใน `EmployeeContext` อยู่แล้ว
