## ปัญหา: พนักงานบางคนอัพโหลดรูปโปรไฟล์ตัวเองไม่ได้

### สาเหตุ (ตรวจสอบแล้ว)

หน้าโปรไฟล์พนักงาน (`/employees/:id`) มีปุ่มกล้องให้อัพโหลดรูป โดยเรียกฟังก์ชัน `updateEmployee()` ที่สั่ง `UPDATE` ตาราง `employees` ตรงๆ

แต่กฎความปลอดภัยระดับแถว (RLS) ของตาราง `employees` สำหรับการแก้ไข อนุญาตเฉพาะ:
- ผู้ที่เป็น **admin**, หรือ
- ผู้ที่มีสิทธิ์ **แก้ไข (edit) โมดูลพนักงาน**

พนักงานทั่วไปถูกจำกัดสิทธิ์ให้ดูได้เฉพาะข้อมูลตัวเอง และ**ไม่มีสิทธิ์ edit โมดูลพนักงาน** ดังนั้นเมื่อพนักงานกลุ่มนี้กดอัพโหลดรูปตัวเอง คำสั่งบันทึกจะถูก RLS ปฏิเสธ → รูปไม่ถูกบันทึกลงฐานข้อมูล

ที่แย่กว่านั้น: โค้ด `handlePhotoUpload` เรียก `updateEmployee` แบบ**ไม่ await และไม่ดัก error** แล้วขึ้นข้อความ "อัพโหลดรูปภาพสำเร็จ" ทุกครั้ง ทำให้ผู้ใช้เห็นรูปขึ้นชั่วคราว (จาก state ในหน้าจอ) แต่พอรีเฟรชรูปหายไป เพราะจริงๆ บันทึกไม่ผ่าน

สรุป: "พนักงานบางคน" = คนที่ไม่มีสิทธิ์ admin/edit (พนักงานทั่วไป) — ส่วน admin/HR อัพโหลดได้ปกติ

### วิธีแก้

**1. เพิ่มฟังก์ชันฐานข้อมูลสำหรับอัพเดตรูปตัวเองอย่างปลอดภัย** (migration)

สร้างฟังก์ชัน `SECURITY DEFINER` ชื่อ `update_own_employee_photo(_photo_url text)` ที่อัพเดตเฉพาะคอลัมน์ `photo_url` ของแถวที่ `user_id = auth.uid()` เท่านั้น แล้ว `GRANT EXECUTE` ให้ `authenticated`

วิธีนี้ทำให้พนักงานเปลี่ยน**ได้เฉพาะรูปของตัวเอง** โดยไม่เปิดช่องให้แก้ฟิลด์อื่น (เงินเดือน/สิทธิ์/ตำแหน่ง) ซึ่งตรงกับข้อกำหนดที่พนักงานถูกจำกัดสิทธิ์ให้ดูเฉพาะตัวเอง

**2. แก้หน้า `EmployeeProfile.tsx`**

- ปรับ `handlePhotoUpload` ให้ตรวจว่ากำลังดูโปรไฟล์ของตัวเองหรือไม่ (เทียบ `employee.userId` กับ user ที่ล็อกอิน)
  - ถ้าเป็นโปรไฟล์ตัวเอง → เรียก RPC `update_own_employee_photo` (ใช้ได้กับทุกบทบาท)
  - ถ้าเป็น admin/HR แก้ให้คนอื่น → ใช้ `updateEmployee` เดิม
- ใส่ `await` + `try/catch` จริง: ถ้าบันทึกไม่สำเร็จให้ขึ้น toast error แทนที่จะขึ้น "สำเร็จ" หลอกๆ

**3. (เสริม) รองรับไฟล์รูปจากมือถือให้ดีขึ้น**

ปัจจุบันถ้าอัพโหลดไฟล์ที่แคนวาสถอดรหัสไม่ได้ (เช่น HEIC จาก iPhone บางเครื่อง) จะได้ error เงียบๆ — จะเพิ่มข้อความแจ้งเตือนที่ชัดเจนขึ้นให้ผู้ใช้ทราบว่าให้แปลงเป็น JPG/PNG ก่อน

### ผลลัพธ์
พนักงานทุกบทบาทจะอัพโหลดรูปโปรไฟล์ของตัวเองได้ และถ้ามีข้อผิดพลาดจริงจะได้รับข้อความแจ้งเตือนที่ถูกต้อง ไม่ขึ้น "สำเร็จ" ทั้งที่บันทึกไม่ผ่าน
