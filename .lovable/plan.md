## แผนการแก้ไข

### 1. เพิ่มเครื่องมือวินิจฉัยในหน้า ตั้งค่า → เครื่องสแกน
เพื่อให้เห็นทันทีว่าติดตรงจุดไหน โดยไม่ต้องเดา
- แถบสถานะต่อเครื่อง: **"ยังไม่เคยมีข้อมูลเข้า"** / **"เชื่อมต่อล่าสุดเมื่อ…"** อ่านจาก `adms_last_seen`
- ปุ่ม **"ตรวจสอบ Endpoint"** — ยิง `/facescan-adms/ping` แล้วแสดงผลจริง
- ช่อง **"Relay URL"** ให้กรอกโดเมน relay ต่อเครื่อง พร้อมปุ่มทดสอบ `/<relay>/health` และ `/<relay>/iclock/cdata?SN=<SN>` เพื่อยืนยันว่า relay ส่งต่อถึงระบบจริง (ผลจะโผล่ใน Sync Logs ทันทีถ้าถึง)
- กล่องคำแนะนำแบบทีละขั้น (ภาษาไทย) พร้อมค่าที่ต้องกรอกในเมนูเครื่อง HIP คัดลอกได้

### 2. เก็บค่า Relay URL ลงฐานข้อมูล
เพิ่มคอลัมน์ `relay_url` ใน `face_scan_devices` (ค่าปัจจุบัน `server_ip`/`server_port` เป็นของโหมด Bridge เดิม) เพื่อให้หน้าตั้งค่าแสดงและทดสอบได้ตรงกับที่ตั้งในเครื่อง

### 3. ปรับ Edge Function `facescan-adms` ให้วินิจฉัยง่ายขึ้น
- บันทึก log ทุกครั้งที่มี request เข้ามา แม้ SN ไม่ตรง (ตอนนี้ทำแล้วบางส่วน) — เพิ่มการบันทึก `POST /cdata` ที่ไม่มีแถวข้อมูล และเก็บ IP/User-Agent ต้นทางไว้ใน `command_payload` เพื่อยืนยันว่าเป็นเครื่องจริง
- ตอบ handshake ให้ครบตามที่ HIP ต้องการ และเพิ่ม log กรณี path ไม่ตรง

### 4. เตือนเรื่องการผูกรหัสพนักงาน
หน้า "ผูกรหัสเครื่องสแกน" จะขึ้นแจ้งเตือนว่าตอนนี้ผูกแล้วเพียง 1 คน — ถ้าไม่ผูก แม้ข้อมูลเข้ามาก็จะถูกข้ามทั้งหมด (ระบบจะสรุปจำนวน "ข้ามเพราะไม่พบรหัส" ใน Sync Logs ให้ชัด)

### 5. งานที่ต้องทำฝั่งคุณ (ผมทำแทนไม่ได้)
1. Deploy ไฟล์ `facescan-relay/main.ts` ขึ้น Deno Deploy (ฟรี) → ได้โดเมนเช่น `ense-facescan.deno.dev`
2. ที่เครื่อง HIP เมนู **Comm → Cloud Server (ADMS)** ตั้ง
   - Server Address = โดเมน relay (ไม่ต้องใส่ `https://`)
   - Server Port = `443`, Enable HTTPS = ON, Enable Domain Name = ON
   - แล้ว **Reboot** เครื่อง
3. กลับมากรอก Relay URL ในหน้าตั้งค่า → กด "ทดสอบ" → ถ้าเขียวคือครบวงจร

ผมสามารถช่วยไล่ทีละขั้นตอนตอนคุณทำที่หน้าเครื่องได้ด้วยครับ
