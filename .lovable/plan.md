## ผลการตรวจสอบ Roles ของพนักงานทั้งหมด

### สิ่งที่ถูกต้องอยู่แล้ว ✅
- พนักงานทั้งหมด **85 คน** — มีบัญชีเข้าระบบ 59 คน, ยังไม่มีบัญชี 26 คน (ปกติ เพราะบางคนยังไม่ได้สร้าง user account)
- **ไม่มีความไม่ตรงกัน** ระหว่าง `employees.role` กับ `user_roles.role_name` ทุกคนตรงกันหมด
- **ไม่มี** user ที่มี role ซ้ำซ้อน, role ว่าง (NULL), หรือ role ที่ชี้ไปยัง role ที่ไม่มีอยู่จริง
- Base roles (admin, hr, manager, employee, executive) มีสิทธิ์ครบทั้ง **27 module** ทุก role

### ข้อบกพร่องที่พบ ❌
Custom role 2 ตัวมีสิทธิ์ไม่ครบ — ขาด module **`ot_management` (ระบบจัดการโอที)**:
- `team_lead` — มี 26/27 module
- `personnel` — มี 26/27 module

**สาเหตุ**: 2 role นี้ถูกสร้างก่อนที่จะมีการเพิ่ม module "ระบบจัดการโอที" เข้าระบบ และฟอร์มบันทึก role จะเพิ่ม module ที่ขาดเฉพาะตอนกด "บันทึก" ใหม่เท่านั้น (upsert ไม่เคยลบ row เดิม) จึงทำให้ record ของ module ใหม่ไม่เคยถูกสร้าง

**ผลกระทบ**: เนื่องจากระบบตั้งค่าว่า "module ที่รู้จักแต่ไม่มี record = ปฏิเสธการเข้าถึง" หากมีการมอบหมาย role `team_lead`/`personnel` ให้พนักงาน คนนั้นจะถูกบล็อกจากหน้าจัดการโอทีโดยอัตโนมัติ และตารางสิทธิ์ในหน้าตั้งค่าจะแสดงไม่ครบ

> หมายเหตุ: ปัจจุบันยังไม่มีพนักงานคนใดถูกตั้งเป็น team_lead/personnel จึงยังไม่มีผู้ได้รับผลกระทบจริง แต่เป็นข้อบกพร่องแฝงที่ควรแก้

## แนวทางแก้ไข

### 1. เติมข้อมูลสิทธิ์ที่ขาด (Backfill)
เพิ่ม record `ot_management` ให้ `team_lead` และ `personnel` (และเผื่อเช็ก role อื่นทุกตัวให้ครบทุก module ในคราวเดียว) โดยตั้งค่าเริ่มต้นเป็น **ปิดสิทธิ์ทั้งหมด** (view/add/edit/delete/approve = false, scope = self) เพื่อความปลอดภัย — จากนั้นแอดมินสามารถเปิดสิทธิ์ที่ต้องการเองได้ในหน้า "สิทธิ์ผู้ใช้งาน"

### 2. ป้องกันไม่ให้เกิดซ้ำในอนาคต
เพิ่มการ **auto-heal** ในหน้าตั้งค่า Roles: เมื่อโหลดข้อมูล ถ้าพบว่า role ใดขาด module (เทียบกับรายการ module ปัจจุบัน) ให้เติม record ที่ขาดด้วยค่าเริ่มต้นปิดสิทธิ์โดยอัตโนมัติ วิธีนี้จะทำให้ทุก role มีสิทธิ์ครบทุก module เสมอ แม้จะมีการเพิ่ม module ใหม่เข้าระบบภายหลัง

## รายละเอียดทางเทคนิค
- **Backfill**: ใช้คำสั่ง INSERT เติม `role_permissions` สำหรับทุกคู่ (role_name, module) ที่ยังขาด โดยดึง `display_order` และ `role_description` เดิมของแต่ละ role มาใช้ ตั้งค่า flag ทั้งหมดเป็น false และ scope = 'self'
- **Auto-heal**: แก้ `src/components/settings/RolesSettings.tsx` ใน `loadData` — หลังดึงข้อมูล เปรียบเทียบ module ของแต่ละ role กับ `uniqueModuleConfigs` แล้ว upsert record ที่ขาด (onConflict: role_name,module) ก่อนแสดงผล
- ไม่มีการแตะ RLS/ฟังก์ชัน DB อื่น เพราะ `can_access_module`, `can_view_employee_data`, `has_role` ทำงานกับ `role_name` อยู่แล้วและถูกต้อง
