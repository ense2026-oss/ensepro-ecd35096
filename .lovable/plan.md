## เป้าหมาย
อัปเดตและเพิ่มข้อมูลพนักงานจากไฟล์ Excel `ประวัติพนักงาน2569.xlsx` (83 รายชื่อ) เข้าสู่ระบบ (ปัจจุบัน 62 คน) พร้อมเพิ่มฟิลด์ใหม่ตามที่ตกลง

ตามที่ยืนยัน:
- **พนักงานใหม่**: เพิ่มทุกคนที่เกินจาก 62 คน (ใช้ fuzzy matching ป้องกันซ้ำซ้อน)
- **ข้อมูลคนเดิม**: เติมเฉพาะช่องที่ว่าง ไม่ทับข้อมูลที่มีอยู่แล้ว
- **ฟิลด์ใหม่**: เพิ่มครบทั้งหมด

---

## ส่วนที่ 1 — เพิ่มฟิลด์ใหม่ในฐานข้อมูล (migration)
เพิ่มคอลัมน์ลงในตาราง `employees`:

| คอลัมน์ใหม่ | ความหมาย | ชนิด |
|---|---|---|
| `gender` | เพศ | text |
| `trial_end_date` | วันผ่านทดลองงาน | text |
| `contract_end_date` | วันสิ้นสุดสัญญา | text |
| `bank_account` | เลขบัญชีธนาคาร | text |
| `driver_license` | เลขใบขับขี่ | text |
| `sons` | จำนวนบุตรชาย | integer (default 0) |
| `daughters` | จำนวนบุตรหญิง | integer (default 0) |

ใช้ `DEFAULT ''` / `0` เพื่อไม่ให้ข้อมูลเดิมพัง (ไม่ต้องแก้ GRANT/RLS เพราะเป็นตารางเดิม)

## ส่วนที่ 2 — เชื่อมฟิลด์ใหม่เข้ากับแอป
- `EmployeeContext.tsx`: เพิ่มฟิลด์ใน interface `Employee` + ใน `dbToEmployee` (อ่าน) + `employeeToDb` (เขียน) + เพิ่มชื่อคอลัมน์ใน select ของ `fetchEmployees`
- `EmployeeFormDialog.tsx`: เพิ่มช่องกรอกในฟอร์ม
  - ข้อมูลพื้นฐาน: เพศ (เลือก ชาย/หญิง)
  - ข้อมูลการทำงาน: วันผ่านทดลองงาน, วันสิ้นสุดสัญญา
  - บัญชี/เอกสาร: เลขบัญชีธนาคาร, เลขใบขับขี่
  - ครอบครัว: จำนวนบุตรชาย, จำนวนบุตรหญิง

## ส่วนที่ 3 — นำเข้า/อัปเดตข้อมูลจาก Excel
เขียนสคริปต์นำเข้า (รันใน sandbox + เขียนผ่าน insert/update) โดย:

1. **อ่านไฟล์ Excel** 83 รายการ + ทำความสะอาดข้อมูล (ตัดช่องว่าง, แปลงวันที่, รวมที่อยู่แบบโครงสร้างเป็นข้อความเดียว)
2. **จับคู่กับพนักงาน 62 คนในระบบ** ด้วยลำดับความสำคัญ:
   - คู่ที่ 1: เลขบัตรประชาชน (`national_id`) ตรงกัน
   - คู่ที่ 2: ชื่อ+นามสกุล แบบ fuzzy (รองรับการสะกดต่างเล็กน้อย ~21 เคส เช่น ณัฐลักษณ์ vs ณัฏฐลักษณ์)
3. **คนเดิมที่จับคู่ได้** → `UPDATE` เฉพาะคอลัมน์ที่ปัจจุบันว่าง (`''`/`null`/`0`) เท่านั้น
4. **คนที่จับคู่ไม่ได้** → `INSERT` เป็นพนักงานใหม่ (ตั้งค่า default ครบ ไม่สร้างบัญชี auth/login ในขั้นนี้)
5. สรุปรายงานหลังรัน: เพิ่มใหม่กี่คน, อัปเดตกี่คน, ฟิลด์ที่เติม

---

## หมายเหตุทางเทคนิค
- การ migration จะถูกขออนุมัติก่อนรัน
- การจับคู่จะแสดงรายการ "คู่ที่สงสัย" (fuzzy score ปานกลาง) ให้ตรวจสอบก่อนยืนยัน เพื่อกันการสร้างซ้ำ
- สคริปต์ใช้ `national_id` เป็น key หลักเพื่อความแม่นยำสูงสุด
- ไม่แตะระบบ auth/รหัสผ่าน — พนักงานใหม่จะยังไม่มีบัญชีล็อกอินจนกว่าจะสร้างผ่านเมนูจัดการบัญชีภายหลัง
